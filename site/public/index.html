Your environment is the starting point.

A valid query can still ask the wrong data the wrong question. CQLmatic maps sources, fields, parser declarations, measured populations, and optional sample values into a reusable environment pack.

Analysts and agents can consult the saved map offline for investigations and reasoning, independently of query generation.

Parser declarations, measured evidence, and pending work stay distinct in status.

Field evidence
With --require-observed, generation withholds the query when referenced deployment fields lack qualifying evidence in the selected snapshot.
Local construction
Recipes, typed plans, and bounded English use one deterministic construction pipeline with no model calls. Typed plans support joins and linked searches.
Query safeguards
Keep matching, missing-field choices, and exact versus estimated distinct counts explicit. Check supported hazards, including grouping ceilings even with limit=max.

From setup to your first query.

Use your assistant alongside the CLI.

  1. Connect your client

    cqlmatic setup

    Guided setup for CrowdStrike MCP. Complete the required consent and Falcon permissions with your administrator.

  2. Choose inventory depth

    cqlmatic env inventory

    Quick inventory scouts selected sources with an authorized target and budget. Full inventory adds parser review and broader measurement. Saved progress can be resumed.

  3. Check context, then write

    cqlmatic status

    Basic generate and check work without discovery. Both inventory modes reuse their matching saved map automatically for writing and result assessment. Use status --json --summary to inspect the target and evidence.

Reading the map requires its location and local access. Discovery does not automatically populate agent context or persistent memory. Bundled CQL and CPS/ECS references are also searchable offline.

Know what you need.

CQLmatic writes and checks queries locally. Your assistant supplies the model; your authorized CrowdStrike client executes searches.

  • A local execution path. An assistant must be able to run the binary. A web chat with only a remote MCP connection cannot do that.
  • Authorized discovery access. MCP handles scouting and search. Parser inventory uses a separate Falcon API connection with NGSIEM Parsers: READ.
  • Time for deeper mapping. Basic query writing needs no discovery. Full inventory can run many searches and consume substantial time and model tokens. Review scope and limits first.
  • Live confirmation when it matters. A local ready result means construction and checking passed. It does not prove vendor compilation, execution, complete results or unrestricted-English accuracy.

About CQLmatic.

CQLmatic’s query mechanics were refined through seven months of development as an internal CQL toolkit, using environment references to write tailored, functional queries. Perfect CQL is the design goal.

The same engine powers the "THIS IS CQL" agent, where those mechanics were used to detect errors in queries generated by CrowdStrike’s own tools.
