- `check` and `generate` warn with `CQL_CORRELATION_SEQUENCE_BY` when `correlate` has at least two mandatory queries with `sequence=true` (or parameterized `sequence`) and `sequenceBy` names a field already equated across mandatory queries by `globalConstraints` or a same-field `<=>` link, where equal values fall back to later `sequenceBy` fields and then `@id` instead of default timestamp ordering.
- `correlate` accepts bracketed mandatory query lists (`query=[...]` or unnamed `[...]`) alongside unnamed query lists and a single `query=label:{...}`, and rejects mixing `query=` or a query list with additional query arguments (`CQL_DUPLICATE_ARGUMENT`).
- `check` and `generate` warn with `CQL_TIME_BUCKET_SERIES_LIMIT` when `bucket` supplies a non-empty `field` or `timeChart` supplies `series` without `limit`, noting the default 10-series cap (maximum 500; `limit=max` is not supported).
- `check` and `generate` warn with `CQL_MATCH_NROWS` when a non-negated `match` against an in-query `defineTable` not proven to fit within the effective `nrows` bound (via a whole-table row bound or, for exact case-sensitive string matching, a `groupBy` returning one row per matched key) imports a non-key column that a later filter or `test()` compares by order (`<`, `<=`, `>`, `>=`), covering omitted `nrows` (default 1), numeric `nrows` (`1..=500`), `nrows=max` (500 rows per event) and parameterized `nrows`, while staying quiet on external lookup files and `remoteTable`.
- `check` and `generate` warn on three additional filter traps: `CQL_EMPTY_STRING_NEGATION` for `field != ""` or `not field = ""` without a prior or sibling-`AND` presence guarantee on `field` (which matches events missing `field`; `test(field != "")` is not reported), `CQL_OR_FREE_TEXT` for pre-aggregate `or` filters mixing a field comparison with bare free text (such as `a = "1" or "2"`), and `CQL_REGEX_PATH_ESCAPE` for single-backslash regex escapes in Windows-path contexts (such as `/[A-Z]:\Windows\System32/`). `check` also warns with `CQL_FILTER_PAREN_SPLIT` when an unquoted `(` immediately follows a filter comparison value (such as `a=x(y)`), which ends the value and parses the rest as a separate filter or free text (`generate` always double-quotes filter values).
