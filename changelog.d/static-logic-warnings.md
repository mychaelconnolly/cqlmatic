- `check` and `generate` warn with `CQL_CORRELATION_SEQUENCE_BY` when `correlate(..., sequence=true, sequenceBy=...)` names a field already equated across mandatory queries by `globalConstraints` or a same-field `<=>` link, where equal values fall back to later `sequenceBy` fields and then `@id` instead of default timestamp ordering.
- `correlate` accepts bracketed mandatory query lists (`query=[...]` or unnamed `[...]`) alongside unnamed query lists and a single `query=label:{...}`, and rejects mixing `query=` or a query list with additional query arguments (`CQL_DUPLICATE_ARGUMENT`).
- `check` and `generate` warn with `CQL_TIME_BUCKET_SERIES_LIMIT` when `bucket` supplies a non-empty `field` or `timeChart` supplies `series` without `limit`, noting the default 10-series cap (maximum 500; `limit=max` is not supported).
- `check` and `generate` warn with `CQL_MATCH_NROWS` when a non-negated `match` against an unaggregated in-query `defineTable` imports a non-key column that a later filter or `test()` compares by order (`<`, `<=`, `>`, `>=`), covering omitted `nrows` (default 1), numeric `nrows`, `nrows=max` (500 rows per event) and parameterized `nrows`, while staying quiet on external lookup files, `remoteTable` and one-row-per-key `defineTable`s.
- `check` and `generate` warn on four additional filter traps: `CQL_EMPTY_STRING_NEGATION` for `field != ""` or `not field = ""` without a prior or sibling-`AND` presence guarantee on `field` (which matches events missing `field`; `test(field != "")` is not reported), `CQL_OR_FREE_TEXT` for pre-aggregate `or` filters mixing a field comparison with bare free text (such as `a = "1" or "2"`), `CQL_REGEX_PATH_ESCAPE` for single-backslash regex escapes in Windows-path contexts (such as `/C:\Windows\System32/`), and `CQL_FILTER_PAREN_SPLIT` for an unquoted `(` immediately following a filter comparison value (such as `a=x(y)`).
