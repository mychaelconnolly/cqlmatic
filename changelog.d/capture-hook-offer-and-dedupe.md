- A verified `setup` for Claude Code, Codex or a Copilot client names the command that installs the capture hook, `cqlmatic env capture --client CLIENT --server SERVER --install`, with the selected server name, and says the name must be the one in the client's tool names; for VS Code Local and other agents it points to the capture hook table and the pass-through. The setup handoff and the agent skill say that where a capture hook or pass-through is registered, discovery results reach CQLmatic without the agent saving them, and to save and submit a result only when `next-probe`'s `next_action` asks for one.
- `env capture --install` updates recognized commands for the same client, server and state in place, preserving fields such as a custom timeout. It keeps distinct custom matchers, deduplicates repeated entries for the same matcher and removes recognized commands with `--hooks none`, including through an alias for the same state. Keep using the same `--program` to manage a hook installed with a custom launcher. Related commands with unrecognized launchers are left for manual review.
- The installer records a confirmed capture registration in `state.json.captures/hooks.json` and ties it to the client settings file. Removing another profile’s hooks leaves the note in place. Its report names the search tool the hook records.
- The capture hook still prints nothing and exits 0, but counts its own failures in `tally.json` when the state file exists: `hook-input-unreadable` for input that is not JSON, `hook-server-not-matched` for a search under a tool name of another server than `--server`, and `hook-not-saved` for a search it could not record.
- Capture cleanup keeps the audits and input files still referenced by the inventory when a hook is reinstalled through a directory alias. Observation replay through that alias reuses the retained audit.
