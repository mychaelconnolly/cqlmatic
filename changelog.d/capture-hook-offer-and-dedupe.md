- A verified `setup` for Claude Code, Codex or a Copilot client names the command that installs the capture hook, `cqlmatic env capture --client CLIENT --server SERVER --install`, with the selected server name, and says the name must be the one in the client's tool names; for VS Code Local and other agents it points to the capture hook table and the pass-through. The setup handoff and the agent skill say that where a capture hook or pass-through is registered, discovery results reach CQLmatic without the agent saving them, and to save and submit a result only when `next-probe`'s `next_action` asks for one.
- `env capture --install` updates recognized commands for the same client, server and state in place, preserving fields such as a custom timeout. It keeps one recognized command per event and removes recognized commands with `--hooks none`. Hooks that wrap the command in a pipeline or use different launchers for different shells are left for manual review.
- The installer records a confirmed capture registration in `state.json.captures/hooks.json` and clears that registration's note when capture is removed or the hooks cannot be confirmed. Its report names the tool name the hook matches.
- The capture hook still prints nothing and exits 0, but counts its own failures in `tally.json` when the state file exists: `hook-input-unreadable` for input that is not JSON, `hook-server-not-matched` for a search under a tool name of another server than `--server`, and `hook-not-saved` for a search it could not record.
