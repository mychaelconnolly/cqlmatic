- Inventory status says what each progress word covers and what is still open. Full and summary status add `completion_detail`: the review time of the current evidence fingerprint (null unless `reconciliation` is `done`), a note that a recorded review is not a completion claim, the number of expected sources whose interpretation review, parser review or binding, or measurements are not done, whether the parser catalog is captured, whether a prepared census is awaiting its capture, and the row count of the most recently imported census with whether it reached the 10,000-row ceiling. Brief status carries the counts and flags. Each field in full status adds `values_saved`, true when the map holds an observed value for it, so a requested value sample that saved no value shows `values: done` with `values_saved: false`.
- `reconcile` returns what it recorded: `status` is `recorded` when it saved a new evidence fingerprint and `already-current` when the saved fingerprint already matched, with the fingerprint, the review time, the same counts and a `next_action` naming the first open category. Brief output gives `recorded` or `already-current` as the action `outcome`, where 0.1.13 gave `applied` and its full output's action was null.
- `full_map_complete` also requires a search-all census below the 10,000-row ceiling that the refresh freshness check accepts. A Full inventory whose search-all censuses all reached the ceiling is no longer reported complete, and status says why in `next_actions`.
- Text status shows scouting as `census saved`, the parser catalog as `captured`, reconciliation as `evidence review current` and a completed discovery run as `run complete, pack activated` where it showed `DONE` or `complete`, and adds a line with the open counts. JSON values are unchanged.
