- Inventory status says what each progress word covers and what is still open. Full and summary status add `completion_detail`: the review time of the current evidence fingerprint (null unless `reconciliation` is `done`), a note that a recorded review is not a completion claim, the number of expected sources whose interpretation review, parser review or binding, or measurements are not done, whether the parser catalog is captured, whether a prepared census is awaiting its capture, the row count of the most recently imported census with whether it reached the 10,000-row ceiling, and `next_action`, the first listed step. Brief status carries the counts, flags and `next_action`. Each field in full status adds `values_saved`, true when the retained pack holds an observed value for it, so a requested value sample that saved no value shows `values: done` with `values_saved: false` when the retained pack has no earlier observed value.
- `reconcile` returns what it recorded: `status` is `recorded` when it saved a new evidence fingerprint and `already-current` when the saved fingerprint already matched, with the fingerprint, the review time, the same counts and a `next_action` naming the first listed step. Brief output gives `recorded` or `already-current` as the action `outcome`, where 0.1.13 gave `applied` and its full output's action was null, and carries the action's `next_action`.
- Status and reconcile advise next steps in one shared order: confirm the target (a `selected-sources` target for Quick discovery), then settle a capability attempt, a refresh, a retained discovery run named by its `run_index` (or restore its missing checkpoint) and a prepared scout, then the work the confirmed mode and scope need. A saved scout response is imported before any new search is advised, and a scout plan the current mode cannot import is replaced with `prepare-scout`. While a blocker is open, status lists no step that prepares a new search. Full-environment work after a completed Full selected-source scope starts with `Full-environment map: `, and Full-discovery work in Quick mode starts with `Full discovery: `.
- `full_map_complete` also requires a search-all census below the 10,000-row ceiling that the refresh freshness check accepts. A Full inventory whose search-all censuses all reached the ceiling is no longer reported complete, and status says why in `next_actions`: no search-all census is saved (even when a named-view census is), the latest one reached the row ceiling, or its rows did not pass census validation.
- Text status shows scouting as `census saved`, the parser catalog as `captured`, reconciliation as `evidence review current` and a completed discovery run as `run complete, pack activated` where it showed `DONE` or `complete`, and adds a line with the open counts. JSON values are unchanged.
