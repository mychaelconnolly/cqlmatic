- Optional function capability checks no longer leave a run that can neither dispatch nor be replaced while no search is outstanding. `prepare-capabilities` refuses a `max_seconds` that does not exceed the host evidence's `max_search_seconds`, before saving anything, and names the smallest value that can dispatch: each dispatch needs `max_search_seconds` of active time left, counted from preparation. 0.1.13 accepted such a run, and no later dispatch from it could pass. A retained run with less than `max_search_seconds` of active time left no longer blocks a new preparation and keeps its history; 0.1.13 blocked it until its whole allowance had passed. A paused run no longer blocks preparing cases it does not hold, and a refusal for an active run asks to pause it first. Preparing a case held by a retained run that can still dispatch and has a case not yet verified is still refused, so that run's original remaining allowance is kept, and an unresolved attempt still blocks preparing and dispatching. `dispatch-capability` now says which condition stopped it (an unresolved attempt, a different execution context or session, a case the run does not hold or holds at an earlier revision, no attempts left, too little active time, or a paused run) and what to do next, where 0.1.13 gave one message for all of them.
