- Optional function capability checks no longer leave a run that can neither dispatch nor be replaced while no search is outstanding. `prepare-capabilities` refuses a `max_seconds` that does not exceed the host evidence's `max_search_seconds`, before saving anything, and names the smallest value that can dispatch: each dispatch needs `max_search_seconds` of active time left, counted from preparation. 0.1.13 accepted such a run, and no later dispatch from it could pass. A retained run with less than `max_search_seconds` of active time left no longer blocks a new preparation and keeps its history; 0.1.13 blocked it until its whole allowance had passed. A paused run no longer blocks preparing cases it does not hold, and a refusal for an active run asks to pause it first. Preparing a case held by a retained run that can still dispatch and has a case not yet verified is still refused, so that run's original remaining allowance is kept, and an unresolved attempt still blocks preparing and dispatching. `dispatch-capability` now says which condition stopped it (an unresolved attempt, a different execution context or session, a case the run does not hold or holds at an earlier revision, no attempts left, too little active time, or a paused run) and what to do next, where 0.1.13 gave one message for all of them. Preparing a case that a retained run in the same host session can still dispatch is refused under every execution context, not only the run's own, and a case whose revision changed no longer releases the run's unchanged cases. A run whose cases at their current revision are all verified dispatches no further attempts and cannot be resumed, also after a later release revises another of its cases; prepare a new run to check a case again. `resume-capabilities` refuses a paused run that has no more than `max_search_seconds` of active time left, and a paused run while another run for the same execution context and session can still dispatch and is active. A dispatch refusal whose next step is a new preparation points first to another retained run that already holds the case, or asks to pause an active one. A refusal that leads to resuming a paused run asks first to pause another run for its execution context and session that is active. An unresolved attempt's refusal names `submit-capability`, and reaching the limit of 100 retained capability runs names a separately initialized inventory.
