- `check` warns with `CQL_JOIN_MAX` when a `join` without `max` includes a field, other than a join key, that a later filter or `test()` compares with `<`, `<=`, `>` or `>=`, as a time-window test does: `join` keeps one matching subquery row per key unless `max` is set, so the comparison may test only one of several matches. Only the field and its `:=` or `eval` copies are followed, and any other stage ends the check. A subquery that returns one row, or ends in a `groupBy` on exactly the join keys with a one-row function, is not reported. `CQL_UNEXPORTED_FIELD` names a field that a correlate does not export and the named query it was expected from, if any, including a field that a named query removes before correlate reads it. A read that `CQL_DROPPED_FIELD` also reports gets both. Some of these fields had no warning before, only the `grounding.basis` note "not exported by preceding query". With `--require-observed` the field stays in `grounding.missing` instead of a warning.
