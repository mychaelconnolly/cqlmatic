- For Claude Code and Codex, `env capture --install` also writes a search guard: a `PreToolUse` hook that checks each NG-SIEM search before the client runs it, whether or not the agent used CQLmatic. The guard refuses the search, with check's errors as the reason, only when check finds `CQL_ARGUMENT_RANGE`, `CQL_ARGUMENT_REQUIRED`, `CQL_ARGUMENT_UNKNOWN`, `CQL_ASSIGN_ALIAS`, `CQL_DUPLICATE_ARGUMENT`, `CQL_FUNCTION_FILTER_COMPOSITION`, `CQL_QUOTE` or `CQL_RESERVED_WORD`. Any other error or warning, or a part of the query check does not cover, reaches the agent as a note and the call goes on, without a permission decision. The guard uses the inventory's map only for a search of the map's view, saves nothing, and exits 0 on every path. Both hook entries run one command that ends with exit status 0 and no output when the program is missing, an older copy rejects the arguments, or a `--program` prefix does not parse; Claude Code's guard entry sets `"onFailure": "continue"`, and both guard entries a 5-second timeout. `--hooks capture,guard`, `capture`, `guard` or `none` chooses the hooks to keep, and removing one keeps every other byte of the settings file. An entry now counts as installed only when it equals the entry the installer writes, so one with an added key, which 0.1.10 reported as installed, is reported as `manual`, as is any other entry that runs CQLmatic for the same server and state. The install report's `event` is replaced by the list `events`, and a new `hooks` object gives each hook's result. Run the install command again after upgrading: it replaces the capture entry 0.1.10 wrote for the same program, server and state. Before going back to an earlier release, remove both hooks with `--hooks none`. Grounding decodes the map once per check instead of once for each field the query reads.
