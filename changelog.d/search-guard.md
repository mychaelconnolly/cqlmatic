- For Claude Code and Codex, `env capture --install` also writes a search guard: a `PreToolUse` hook that checks each NG-SIEM search before the client runs it, whether or not the agent used CQLmatic, and tells the agent what check found. The guard never stops a search and makes no permission decision. For a query check calls `invalid`, the agent gets a note that check expects the search platform to reject it, listing check's errors before its warnings; any other error or warning gets a note too, and a clean query gets nothing. The guard uses the inventory's map only for a search of the map's view, and saves nothing. Both hook entries run one command that ends with exit status 0, with no output when the program is missing, an older copy rejects the arguments, or a `--program` prefix does not parse; on macOS and Linux also when a `--program` prefix prints a line and then fails to start its program, and when the client's shell is set to exit at the first failing command, as zsh is with `setopt ERR_EXIT` or bash with `set -e`. Claude Code's guard entry sets `"onFailure": "continue"`, and both guard entries a 5-second timeout. `--hooks capture,guard`, `capture`, `guard` or `none` chooses the hooks to keep, and removing one keeps the rest of the settings file's content and formatting. An entry now counts as installed only when it equals the entry the installer writes, so one with an added key, which 0.1.10 reported as installed, is reported as `manual`, as is an entry that another copy of CQLmatic wrote for the same client, server and state. Several identical copies of the installer's entry are reduced to one. The install report's `event` is replaced by the list `events`, and a new `hooks` object gives each hook's result. Run the install command again after upgrading: it replaces the capture entry 0.1.10 wrote for the same program, server and state. Before going back to an earlier release, remove both hooks with `--hooks none`. Grounding decodes the map once per check instead of once for each field the query reads.
