- With an environment map, `check` and `generate` warn about what the map lacks. `CQL_UNMAPPED_SOURCE` reports a `#repo` or `#type` value that matches no mapped source, names mapped selectors, and says when an unmatched value is the target view's name. `CQL_UNMAPPED_FIELD` reports a field that no selected source lists as observed, documented or declared, naming those sources, and a field whose exact record the map measured and did not observe, with its measurement window. Paths compare segment by segment, ignoring the number in an array index but not its position, and `#name` and `name` are different fields. A field listed only as documented or declared, a member the map has no record of inside an object or array it documents, a field or array the query produces, a source's recorded dataset and record-kind fields, and `@` metadata fields are not reported. `in()` selectors on `#repo` or `#type` are not compared. Reading a field that an earlier step removed warns `CQL_DROPPED_FIELD`, with or without a map, but only when no step between them can create fields. An array the query writes by index now counts as query-produced, so `--require-observed` no longer asks for deployment evidence for it and Quick mode no longer saves it as an unverified field lead; strict mode adds none of these warnings. `CQL_GROUNDING_LENIENT` is removed: 0.1.10 emitted it, with or without a map, for any ready query reading a field without qualifying observed evidence, so `--fail-on-warning` exited 1 for such queries. `grounding.basis` keeps the evidence for each field.
