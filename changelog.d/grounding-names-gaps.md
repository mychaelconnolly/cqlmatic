- With an environment map, `check` and `generate` warn about what the map lacks. `CQL_UNMAPPED_SOURCE` reports a `#repo` or `#type` value that matches no mapped source, names mapped selectors, and says when an unmatched value is the target view's name. `CQL_UNMAPPED_FIELD` reports a field that no selected source lists as observed, documented or declared, naming those sources, and a field the map measured and did not observe, with its measurement window. `#name` and `name` are different fields. A field listed only as documented or declared, a field or array the query produces, a source's recorded dataset and record-kind fields, and `@` metadata fields are not reported. Reading a field that an earlier step removed warns `CQL_DROPPED_FIELD`, with or without a map. A single literal `in()` on `#repo` or `#type` now selects a source like `=`, and an array the query writes by index counts as query-produced; `--require-observed` can therefore give a different outcome for such queries, and it adds none of these warnings. `CQL_GROUNDING_LENIENT` is removed: 0.1.10 emitted it, with or without a map, for any ready query reading a field without qualifying observed evidence, so `--fail-on-warning` exited 1 for such queries. `grounding.basis` keeps the evidence for each field.
